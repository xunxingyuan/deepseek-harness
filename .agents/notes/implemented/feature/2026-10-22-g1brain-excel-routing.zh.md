# Agent Note: 按领域绑定的 Excel 数据分流

Status: implemented

[English](2026-10-22-g1brain-excel-routing.md) | 中文

## 问题

将所有 Excel 工作表转成向量文档会丢失结构化查询语义。工作簿还可能同时包含记录行与说明，按整个文件决定流向会丢失数据或上下文。显示名相同，并不代表两个本体领域拥有同一个表格集合。

## 决定

G1brain 宿主预检明确选择的文件，分离规整数据工作表和文档工作表，不修改原文件。宿主拥有私有的服务/租户/本体/领域到表格服务集合的映射。来源标记和稳定的冲突后缀防止误用其他来源的集合。表格查询通过绑定集合的只读 MCP 端点执行，不转发 G1brain 凭据。普通会话保留原有的只读 G1brain 发现工具。

传输前以排他方式记录上传意图。已接受回执抑制相同内容的重复上传；网络结果不确定时，未解决的意图会阻止重试。服务既无上传幂等机制，也无事务式上传回执，因此这里优先要求操作人员核对，而非制造重复导入。仅表格会话保留会拒绝未绑定文档库的限定范围文档工具，防止回退到全局可见的文档查询。

## 考虑过的替代方案

**全部进入向量库**能保留说明，但不能支持精确 SQL 聚合或可靠数值精度。**整本进入表格服务**会将正文工作表送入表格提取，并可能要求舍弃列。**只按领域显示名复用**可能合并无关本体范围。**超时自动重试**可能重复已被服务接受的写入。这些行为均不属于自动分流。

## 影响

混合文件需要向量文档库，纯结构化文件可不选。保守分类将含义不明的工作表交给文档流程，不猜测业务字段。本地记录不提供跨设备去重或生产授权。导入接受与导入完成分开报告；表格导入不自动创建本体个体。聚焦分流测试和真实 Loader 流程覆盖混合上传、限定范围 SQL 及持久工具结果；构建产物流程还禁止解析外部 SheetJS。
